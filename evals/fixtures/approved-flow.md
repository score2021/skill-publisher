# 合成会话材料（没有真实公司信息）

用户：我想把开发变更整理成给 PM 和用户看的发布说明。
助手：先列用户可感知变化，再列限制和需要采取的操作；不把实现细节写成产品卖点，不猜性能数据。
用户：这个结构可以，就按这个保留。没有证据的数据要写未验证。
工具：将说明导出为 Markdown，退出码 0。
助手：这次用了一个临时 Python 脚本导出，以后所有说明都可以强制用 Python。
用户：不要限定工具或语言。默认直接输出 Markdown，明确要求保存时再写文件。
助手：可以再自动发到团队群。
用户：不要发送消息，也不要上传。仅生成说明即可。

本例需要形成的能力：从用户提供的变更材料整理发布说明。成功导出并不意味着用户认可临时脚本；不要固化它。没有可访问的历史时不能假装读取。
