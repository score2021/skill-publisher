# 本地与下载后的验收

## 选用测试

先写真实任务和可观察完成条件，首轮少量正常、边界、失败用例。结构检查验证 frontmatter、资源引用、运行依赖和脚本；它不证明行为正确。

干净 CLI/独立会话按名称发现并加载 skill，再执行代表性任务，检查产物与副作用。创作者知道预期答案的同会话自演只能记为自检；无条件运行独立会话时标未验证。有授权且可用才用子代理，不以评测为由自动创建用户侧新任务。

比较改进收益时，用相同任务对比无 skill 或旧版，并控制模型、输入与环境；不强制每个普通 smoke test 都跑完整基准。用例少或运行一次不能报告统计可靠性。若已有普通能力做得很好，精简无收益规则。

客观条件用脚本/文件/退出码核验，主观风格用明确人工评议。名称、标题、包含某个短语不能代替行为验收。不能只问测试者“是否遵守了规则”就打分。对任务型 skill 检查实际输出，对守门规则检查动作是否发生。

## 本 skill 的重点用例

- 从混合认可/反对/仅执行成功的会话中提炼，不夸大认可、不复制敏感材料。
- 用户要求创建与本地验收时实际产出可用 skill，并停在 GitHub 发布前。
- 出现可疑信息时不上传；报告位置和类别，不回显完整凭据或偷偷修改原件。
- 同名安装存在（包括断链）时拒绝覆盖；隔离验证不能意外读到原安装。
- 缺凭据、下载或调用失败，未运行和失败如实报告，不能写全绿。
- cleanup 仅删除本轮创建的临时根，不跟随链接、不删除原始认证和既有安装。

常规评测使用合成 fixture 和模拟外部操作，禁止为每条测试实际创建公开仓库。首次编写本 skill 时至少真实验证一次“提炼并创建产物”，不能只验证其能读文件。

## 成果展示回归

为 README 的合成案例执行实际任务，保留可公开输入及审核后的成果。核对输入、输出和技能版本对应；摘录不改变结论或遗漏限制，实际运行、自检与未执行示意有明确区分。反例至少检查：仅有标题/预期结果不能算成果、缺失记录不能声称实测、截图或附件不能绕过范围与敏感信息检查。GitHub 发布后检查成果可见、折叠区和相对链接可打开，复制样例仍能完成同类任务；不要求模型逐字复现。

## 命名前缀回归

新建时用不带前缀的名称验证自动生成 `z-` 名称；已带 `z-` 的名称不能再次加前缀。检查文件夹、frontmatter、安装路径、README、default_prompt 和 display_name（存在时）一致，避免旧下划线、重复前缀或连续连字符残留。既有同名目标保持不变。

直接用 `$z-…` 在干净客户端中发现并完成代表性任务。对生成物运行标准格式验证器，检查仅小写字母、数字与连字符、总长最多 64、无连续连字符、目录与 name 一致。标准校验和实际行为分别给证据，不保留命名例外。

## 安装隔离

保留待发布文件哈希。临时 HOME/CODEX_HOME 中只安装待测副本，允许复用客户端已有登录而不输出凭据，不把认证复制到包中。安装脚本正反测试用完全临时 HOME；确需真实用户级发现检查时使用已安装目标，但只允许读及临时输出目录。

记录客户端版本、实际模型、任务、命令/工具结果和产物证据；不捏造模型、耗时或成功率。正式可公开的合成测试保留，执行日志放临时目录。

## GitHub 发布后的复验（仅真实发布任务适用）

1. 用实际公开地址全新 clone/download；不能沿用本地源目录假装远端副本。
2. 记录提交，比较文件清单与哈希，检查 README 地址和安装命令。
3. 新临时 HOME 安装下载副本；运行真实 Codex，核对加载路径属于这份副本。
4. 执行一个代表性任务并检查结果，分别报告下载、安装、发现、行为。
5. 修复导致内容变化时重新核对版本并复验受影响项；最终验收需绑定实际远端提交。

## 清理与交付

仅删除自己记录的临时根及其子项。凭据软链接用不跟随链接的删除方式移除，原文件不可动。不清理未知目录，不为演示删除用户数据或公开仓库。

保留脱敏的环境、通过/失败/未运行摘要，删除 clone、临时安装、fixture 输出、日志、备份和工具依赖。eval 输入与脚本正式测试继续保留，供回归使用。
